# Design Guidelines

## Design Context

### Scope And Source Of Truth

This repository contains a personal website and independently styled projects. This file covers the personal site only — running-product conventions live in `pacey/.impeccable.md`.

The personal site's audience is intentionally unrestricted. It is a place to explore Terrance's stories, interests, articles and experiments, not a narrowly targeted conversion funnel. Preserve its photographic, personal character, existing typefaces, nature greens and tech blues; prefer small, grounded improvements over a broad visual refresh.

The implementation reference is [`docs/site-design.md`](docs/site-design.md). The visual specimen sheet is [`articles/my-website-style-guide.html`](articles/my-website-style-guide.html); retain its widget/swatch/specimen presentation, not a prose-only essay.

### Personal Site Principles

- Shared components have one styling owner: `styles/site-header.css`, `styles/site-navigation.css`, `styles/site-footer.css`, `styles/site-typography.css` and `styles/site-motion.css`. Change the owner, not per-page utility-class copies. Header markup is still static in each page; it is not generated by a shared template.
- Header and footer navigation share `--site-text-navigation`. Different roles may differ in size: display headings are not body copy, and supporting dates are not navigation. Use the existing type-role tokens rather than introducing independent breakpoint formulas.
- The shared header owns its full layout, including its 1024px desktop breakpoint, title and social icons. Homepage palette differences do not justify separate spacing or corner-radius rules.
- Footer links remain a compact horizontal row, not pills or a two-column phone menu. `js/footer.js` supplies the shared footer and the square, rounded SVG back-to-top control.
- Motion is progressive enhancement: native cross-document transitions only where supported, no intercepted/delayed navigation, reduced-motion alternatives, and no artificial skeleton over already available static text. Touch press feedback and fine-pointer hover effects serve different inputs.
- Reading progress measures the article, not the document footer. Below-fold images use native lazy loading; root-page hero images remain eager and prioritised. Originals stay intact; responsive derivatives and gallery full-resolution links follow the image workflow in the implementation reference.
- Font requests are consolidated in page heads with preconnects; directly linked shared CSS avoids serial discovery through imports. Keep fallback imports aligned with those same sources rather than creating another font or component definition.
- Accessibility requirements are a quality target, not a claim that every legacy page has been audited. Preserve visible focus, zoom, meaningful labels and text alongside colour cues.

### Independent Projects

Pacey uses its own cork/paper tokens and handwriting faces. Light cork copy uses warm brown ink; dark cork copy uses warm cream, while paper stays light with dark ink. Its landing page and app have separate motion contexts; do not impose the personal homepage's replay behaviour on the landing page. Pacey's full design conventions live in [`pacey/.impeccable.md`](pacey/.impeccable.md).

Biwa's authoritative project-specific context is [`projects/biwa-ride/AGENTS.md`](projects/biwa-ride/AGENTS.md). Travel-Rizz's showcase is based on local planner styles, not a verified snapshot of its separately hosted app.
