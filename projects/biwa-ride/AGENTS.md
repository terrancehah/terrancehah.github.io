# AGENTS.md — Lake Biwa Ride Companion

Mobile-first companion for three friends riding Otsu → Hikone → Takashima → Otsu. Public static app at `/projects/biwa-ride/` (linked from the Biwa card in `projects.html`, still `noindex`) backed by isolated Vercel functions `api/biwa-{trip,route,place,photo}.py` with helpers under `lib/biwa/biwa-*.py` (outside `api/` so Vercel's function discovery never builds them). The trip is PERSONAL — every request carries `X-Biwa-Owner` (`dev:<uuid>` minted client-side once); each owner has its own durable Redis doc (`biwa:v2:owner:<id>:trip`, no TTL) holding plan AND check-in progress together. `lib/biwa/biwa-pair.py` mints 10-minute six-character codes so a second of the owner's devices can claim the same id — it is mounted on the biwa-trip function at `POST /api/biwa-trip/pair` and vercel.json rewrites the public `/api/biwa-pair` URL (plus its `/projects/biwa-ride/api/` alias) onto it, so the client never changed. This file is the persistent project doc for the app — do not add README/design docs.

## Design context

Three riders, phones roadside in daylight. Personality: a compact Japanese autumn ride journal — warm, quiet, a little handmade — not a generic dashboard. Repo-level `.impeccable.md` principles carry over (clarity, hierarchy, AA contrast, reduced-motion floor) but Biwa pins its own tokens in `biwa-tokens.css`; no Pacey tokens or board materials.

Palette (exact): `#eee2df` alabaster, `#eed7c5` petal, `#c89f9c` rosy, `#c97c5d` peach, `#b36a5e` clay, plus warm ink `#3a2a26`, lake blue `#2f5d6f`. Soft hues are surfaces only; primary actions use `--biwa-clay-deep` for AA contrast. Momo Trust Display headings (regular 400 only — heading-face elements are pinned to `font-weight: 400` so nothing synthesises a bold; body bolds still use Quattrocento Sans 700), Japanese glyph fallbacks, font-display swap.

Rules of thumb: mobile bottom nav + `env(safe-area-inset-bottom)`; desktop split ≥56rem; 48px touch targets (44px inline/selects); 16px body text; visible focus ring; text+icon status (never colour alone); no emoji icons (inline SVG); flat/lineless surfaces (tinted fills and shadow steps, no decorative borders — the 2px lake focus outline stays); button-first editing, no drag-only actions; honest states over false confidence (missing endpoints, unconfirmed names, unavailable metrics, stale data are labelled, never zeroed/hidden); "Road preview, not cycling guidance" always visible beside route content.

## Data provenance

`data/checkpoints.json` — 33 unique places: the 26 canonical checkpoints (17 official — user's newer dataset; the official site lists 16 — + 10 user-supplied rally stops, shared Mizudori merged into one place with both memberships) plus 7 additional places (3 accommodations, Shirahige Shrine and the legacy Omi-Takashima Station record as custom stops, and 2 `route-waypoint` anchors) that carry verified Google place ids/addresses and `lat`/`lng: null` — provider coordinates are never stored. `source.{longitude,latitude}` preserves supplied pairs; `lat`/`lng` is the explicit conversion. `lib/biwa/biwa-checkpoints.json` is a mechanical copy — the server's immutable manifest; regenerate it whenever the client catalogue changes.

User-requested classification pass (map icons + dataset corrections): `extra-chomeiji-183` and `extra-oura` are `route-waypoint` anchors — they keep their Day 1/Day 2 occurrences and steer the road line but are hidden from the itinerary, checklists and completion (see `Rules.visibleDayPoints` vs `Rules.dayPoints`). `official-west-information` carries an `official-east` programme override despite its west-geography naming — the stable id and canonical coordinates/`googlePlaceId` are unchanged, only the label gained the "(Omi-Takashima Station)" suffix. `extra-takashima-station` is that same physical stop under a legacy id — kept in the manifest for backward compatibility, never rendered as a second pin, and old snapshots referencing it are retargeted client-side by `TripStore._normalizeTrip` (no server write is triggered; the corrected snapshot persists on the next normal save). Normalization migrates `label`/`notes` only while a snapshot still carries the pre-correction default — a rider-renamed label or user-written note is always preserved.

`data/trip-seed.json` — the blueprint 3-day plan. Day boundaries are shared: a day's end is the next day's start. Lodging chain: Day 1 Guest House Hana → Comfort Hotel Hikone, Day 2 Comfort → 临湖庄 (stay-rinkoso — the copied "1-17 Katsuno" address IS this lodging, not a separate place), Day 3 临湖庄 → Biwako rental return. Endpoint rows carry implicit occurrence ids `day-N-start`/`day-N-end` for manual arrival ticks.

Rally window announced 2026-09-01 → 2026-12-31.

`assets/cycling-scene.svg` is a generated illustration kept on disk but NOT used — it was rejected in favour of user-supplied artwork. The full-width `.biwa-masthead` hosts a layered decorative scene (`aria-hidden`, no user controls — motion stops only automatically under `prefers-reduced-motion` or while scrolled offscreen via IntersectionObserver): self-drawn mountains/water/road under bright scene tokens `--biwa-scene-sky/-lake` (art colours, not UI palette; the road is one plain band). Everything on the shore anchors to `--biwa-scene-road-height` (15%) on `.biwa-masthead` — road band, tree belt base, torii base — and the water is `calc(100% - 46% - var)` so no empty strip can open between lake and road. Three rider GIFs at 75% of the original spec (`clamp(67.5px,10.125vw,127.5px)`), wheel-base aligned to the masthead bottom — frames pad 18/256 transparent at the bottom, corrected by `translateY(7.03125%)`. `assets/cyclist-01/02/03-loop.gif` are PIL-derived cadence variants of the supplied `wired-flat-667-…` originals (kept on disk as source): rescaled per-frame delays give each rider a distinct pedalling tempo (slow/baseline/quick). Each rider also runs a per-rider CSS drift loop (`biwa-rider-drift-a/b/c`, selected via per-rider classes `biwa-scene-rider-a/b/c` (positional selectors shifted silently every time an img layer joined)) with inline `--drift-dur`/`--drift-delay` — left rider drops back and occasionally chases through the bunch, middle weaves, right attacks the right edge; subtle `rotate` leans carry effort cues since GIF cadence can't change mid-loop. Every loop returns to `--rider-x` home. Four static supplied landmarks ride the same pass convention — continuous right→left drift, wrap fully offscreen, no fade, all on the same 45s/400vw track (105vw→-295vw ≈ +50% gap, same ~8.9vw/s drift) quarter-spaced in phase (0s/-11.25s/-22.5s/-33.75s ≈ 100vw apart): the torii (`wired-flat-1984-torii.svg`; the `-in-reveal` GIF and `torii-still.png` stay on disk unused) grounded `translateY(13.1%)`, the pagoda (`wired-flat-1940-pagoda.svg`, 168px) at 10.94%, and two shrine PNGs (`shrine-01/02.png`, renamed kebab-case) sharing one parametrized `biwa-shrine-pass` rule via per-img `--shrine-h/--ground-y/--pass-delay` vars (the 512px frames pad ~2-3% below the feet). Roadside walkers come from the supplied `wired-flat-646-…` GIFs, repackaged as `walker-01..05-loop.gif` cadence variants (+10ms delays = slow stroll, dropped frames = brisk) — feet ground at `translateY(6.64%)` (17/256 bottom pad) and heights stay under the tree band (40–60px). `.biwa-scene-walker` imgs ride INSIDE the belt halves (cloned with the tile — the clone copies each walker img's inline style and GIF src verbatim) so their pace is tree speed plus a tiny meander, `--walker-flip:-1` facing them with the scroll; `.biwa-scene-passer` imgs are the counter-flow — own `biwa-walker-pass` loops entering at the right edge (105vw) and drifting left across the whole shore while facing right — a deliberate moonwalk so the riders read as having dropped them — paired by a shared `margin-left`. `assets/tree-01..06.svg` are vector traces (colour-region contours, edge-connected background removed) of crops from the user-supplied `6075400.jpg`, not redrawn — their viewBoxes are trimmed to real path bounds so each visible trunk base lands exactly on the belt's bottom edge. The belt is `max(200%,1800px)` wide: each half's tree count is proportional to its pixel width (JS targets ~76px spacing — the original wide-desktop look — so density is constant phone→desktop; the img pool grows by cloning or hides surplus imgs, and re-arranges on viewport-width drift), assets Fisher-Yates shuffled into singles/pairs/trio groves jittered over 2–97%, then DOM-cloned into the second half for a seamless `-50%` wrap; trip polls never re-randomise. Tree height is owned by the HTML inline `height` per img (editable), CSS only clamps it to 80–100px (`min/max-height`, 90px fallback). Supplied art is user-provided with unknown licence — licensing is the user's responsibility; do not attribute or claim terms. Figure GIFs (riders, walkers, passers) are ALWAYS animated by request — no still swap exists; the `*-still.png` captures stay on disk unused. `.is-paused` and `prefers-reduced-motion` freeze only the CSS layers, and since a GIF's frames can't be paused, the figure imgs are `display: none` under reduced-motion rather than left stepping in place. Browsers suspend decode of never-painted animated images (the belt trio start clipped offscreen inside the transformed belt and could return frozen while their drift still moves), so a per-figure IntersectionObserver rooted on the scene display-flicks each figure img on every real entry — a same-URL `src` reset is a no-op against WebKit's image cache, while detaching and rebuilding the renderer runs the genuine 'in visible rect → start animation' resume path; 1.5s cooldown against clip-boundary flicker.

`assets/maple-leaf.svg` is the OpenMoji maple leaf (source https://github.com/hfg-gmuend/openmoji) preserved unmodified as provenance; the leaf-burst renders `assets/maple-leaf-flat.svg`, a user-requested adaptation of the same silhouette with the outline group removed — used as a CSS mask so each of the 36 leaves is tinted a palette colour (peach/clay/rosy/petal/clay-deep). Both ship under CC BY-SA 4.0 — https://creativecommons.org/licenses/by-sa/4.0/; attribution lives in `terms.html`. Do not recolour or redraw the original; derive flat variants from its `g#color` path only.

## Configuration

| Env var                                        | Purpose                                                                                                                                  |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `BIWA_REDIS_URL`                               | Preferred backend — direct Redis URI (`redis://`/`rediss://`) to the dedicated Biwa DB, used via `lib/biwa/biwa-redis.py`                |
| `BIWA_REDIS_REST_URL`, `BIWA_REDIS_REST_TOKEN` | Dedicated Upstash DB (never Pacey's) — fallback when `BIWA_REDIS_URL` is unset                                                           |
| `BIWA_GOOGLE_SERVER_KEY`                       | Routes + Elevation, server-side                                                                                                          |
| `BIWA_GOOGLE_PLACES_KEY`                       | Places details/photos, server-side — separate from the Routes key so scopes rotate independently; falls back to `BIWA_GOOGLE_SERVER_KEY` |
| `BIWA_GOOGLE_BROWSER_KEY`                      | Maps JS, referrer-restricted; returned to every visitor on the public GET                                                                |
| `BIWA_DEV_ALLOW_MEMORY`                        | `=1` opts into the in-memory backend for local dev only                                                                                  |

There is **no `BIWA_TRIP_TOKEN`** — identity is the `X-Biwa-Owner` header only (unguessable UUID, self-minted); the only guards are same-origin mutation checks, rate limits and body caps. Missing Redis vars → `sharingAvailable: false` on GET (the trip still renders from the seed and provider/browser config stays live; writes fail closed). The `BIWA_DEV_ALLOW_MEMORY=1` in-memory backend is ignored on Vercel (`VERCEL` env present) and is shared across all endpoint stores in one process. Referrer policy is `strict-origin-when-cross-origin` (Google's key needs the origin). The retired shared doc (`biwa:v2:trip:state`) is left in Redis untouched; new traffic never reads it.

`BIWA_REDIS_URL` may be parked in `.env.local` for local use — a value in that file does NOT mean the deployed site has it configured; the Vercel/dashboard env setup is user-owned. The `redis` Python package (requirements.txt) must be installed before the direct-URI backend works; the launcher env does not vendor it. All four endpoint modules share whichever backend resolves, so trip state and rate limits live in one Biwa-namespaced database (durable `TRIP_KEY`, no TTL — the shared trip never expires).

Provider status (as configured): Places (New), Routes and Elevation all work on the current key — real day polylines and sampled ascent paint on the map. If a future key lacks an API, the app reports a specific "enable the Routes API"-style notice and falls back to markers/schematic (never fake metrics or straight-line road claims). Geocoding is not required — do not enable it for this app.

## Local development

One-shot launcher for both servers (loads `.env.local`): `./biwa-dev.sh` at the repo root. When `BIWA_REDIS_URL` is set it takes precedence over `BIWA_DEV_ALLOW_MEMORY=1`, so the Google cache (details/photo names/image bytes, 30-day TTL) survives API restarts — the memory backend is only the fallback when no Redis var is configured. To iterate on UI with **zero provider spend**, open `http://localhost:3000/projects/biwa-ride/?noroute` — `maybeRequestDayRoute` leaves every day 'idle' ("road preview not requested") since route geometry can never be cached and is the one guaranteed billed call per refresh. Or manually:

```bash
# terminal 1 — isolated Biwa API (in-memory store; loads .env.local for the
# Google keys). Kebab-case module name → load by path; use the 3.13 venv.
BIWA_DEV_ALLOW_MEMORY=1 venv/bin/python -c "
import importlib.util, sys, uvicorn
spec = importlib.util.spec_from_file_location('biwa_dev', 'lib/biwa/biwa-dev.py')
m = importlib.util.module_from_spec(spec); sys.modules['biwa_dev'] = m
spec.loader.exec_module(m)
uvicorn.run(m.app, host='127.0.0.1', port=8000, log_level='warning')
"

# terminal 2 — static site + proxy on :3000
node proxy-server.js
```

Open `http://localhost:3000/projects/biwa-ride/` — plain URL, no invite. The proxy forwards only `/projects/biwa-ride/api/biwa-*`. The legacy `api.index` target in `start-dev.sh`/`package.json` is broken and intentionally untouched.

## UX conventions

- `#biwa-mini-bar` is a persistent mini-player-style strip (mobile only, `display:none` ≥56rem): photo slot (petal-tinted fallback, never resizes), place name + badges, an icon-only Navigate link (the Tabler Icons `route` glyph — geometry verbatim, MIT © Paweł Kuna, license at `assets/tabler-icons-license.txt`, attribution in terms.html; `aria-label`/`title` repainted with the stop name) + Check in button. Both actions use the concentric `calc(var(--biwa-radius-md) - var(--biwa-space-sm))` radius — 6px inside the bar's 14px — never the global pill. Rendered at the END of `renderNextCard` from the same resolved `next`/`photo`/`dirEl.href` — never re-derive its state. Its check-in calls the shared `completeNextStop(ev)` (live-resolved, `applyLocalProgress`, toast + leaves); its body opens `openNextStopSheet()`. `mini-checkin.js` (`BiwaMiniCheckin.create`) owns the button's saving → staged-confirmation phase machine: `begin()` before the optimistic emit (the visible 'Check in' text stays while saving; only aria reports the write), `settle(token,result,durableLocal)` on write resolution ('local' counts only with a provably durable mirror), then the staged ack — label exits 140ms → the green tick draws itself over 320ms (Tabler `check` glyph, unit-path `pathLength` dashoffset on the completed wash) → 650ms hold → 'Check in' fades back over 220ms, ~1330ms total. The faces are STRICTLY exclusive: the tick is `hidden` (display:none) in every phase except the acknowledged one and the label is `hidden` inside it — text-only → tick-only → text-only, never opacity-only coexistence — then release re-renders. Reduced motion collapses the staging to a static tick on the same hold. While an episode is active the bar is FROZEN — `renderNextCard` neither repaints nor hides it, the open/directions controls are inert, and a day switch cancels the episode (its stale token can't tick the next day's stop). Shown ONLY while a live next stop exists — finished/empty states hide it (a final-stop check-in stays through the tick, then hides on release). While live it sets `body.biwa-mini-live`, which grows the shell's bottom padding and lifts the toast above the bar (`--biwa-mini-bar-h` keeps all three heights in sync). z-index 32: over nav (30), under sheet (40) and toast (50).
- Row affordances: stop cards read left→right as drag grip → tick → body → chevron (`chevronHint()` — aria-hidden, INSIDE `.biwa-card-body` so the right edge stays in the tap target); endpoint rows drop the grip. `.biwa-card-text` wraps name+meta inside the flex body.
- **Destructive endpoint edits confirm natively.** `endpoint-change.js` (`BiwaEndpointChange.planEndpointChange`, pure) plans every start/overnight edit: the touched day fields (a day's end IS the next day's start), the implicit `day-N-{start,end}` visit ids to retire when identity changes (placeId or pin lat/lng — a label-only pin rename keeps its tick), and `needsConfirmation`. `saveEndpoint` shows a localized `window.confirm` for any non-empty clear and for replacing a checked boundary — cancel writes nothing and leaves the editor open; accept performs one `store.save(..., {clearVisitIds})` that updates both boundary sides and deletes both arrival flags atomically, so no orphan `visitStatus` key can fail server validation. Unchecked replacements never prompt.

## Sync & safety invariants

- **Check-in progress lives in the personal doc.** `visitStatus`/`programmeStatus` travel inside the owner's doc; `TripStore.applyLocalProgress` writes the localStorage mirror (`biwa:v2:local-progress`) first for instant ticks and offline buffering, then persists the whole snapshot through `save()` — the save's mutator pins the mirror _at write time_ so a queued write never resurrects a stale snapshot over a paired device's ticks. `applyLocalProgress` diffs the mirror before/after the mutator and hands `save()` the exact `{progressChanges}` deltas (removals included); those deltas are what a CAS-409 replays onto the fresh server snapshot for an automatic one-retry merge — ordinary paired-device check-ins combine with no keep-mine dialog. Any non-progress save pushes a plan seq that makes the pending work "mixed" and keeps the explicit whole-draft conflict. Outstanding deltas ride inside the durable draft's serialized copy under reserved `_biwaLocalProgress` (stripped before the wire, restored on reload, seq-0); a draft persisted without it is treated as mixed, never auto-merged. Adoption mirrors doc progress back into the local copy (paired same-owner devices' ticks arrive through it) — skipped while a `pendingDraft` holds newer local work. `navigator.storage.persist()` is still requested at boot for the mirror. The CAS intent-rebase machinery is retained — a personal doc can still be edited from two same-owner devices/tabs.
- Owner identity: `biwa:v2:owner-id` in localStorage, sent as `X-Biwa-Owner`. Missing/invalid → 401 `owner_required`, which the client treats as the guard path (local seed/draft only). `TripStore.createPairCode`/`claimPairCode` drive `/api/biwa-pair` (rewritten to `biwa-trip`'s `/pair` route — the module lives in `lib/biwa/biwa-pair.py` to stay under the 12-function cap) but refuse before any fetch when `getPairingBlockReason()` reports `offline` (navigator.onLine/connectionIssue/localOnly), `unsaved_changes` (`hasUnsavedChanges()` — pendingDraft/conflict/in-flight or queued writes/tracked deltas), `not_ready` (state ≠ saved) or `storage_unavailable`; the dialog surfaces the reason inline (status `role="status"`) plus a `data-tone="notice"` toast that hides the success checkmark — offline is never dressed as an invalid code, and a real `code_expired` keeps its own message. The claim handler re-checks the guard before `adoptOwner` (work can arrive mid-flight); `adoptOwner` itself refuses while blocked, verifies every localStorage op before switching `ownerId`, and returns false without a reload on failure — unsaved data is never deleted. The retired shared doc key (`biwa:v2:trip:state`) is never read by new code.
- **`biwa-owner` capability cookie.** `<img src>` photo loads cannot send the owner header, so a successful owner-authenticated `GET /biwa-trip` mints an HttpOnly `biwa-owner` cookie (SameSite=Strict, Path=/, Secure on HTTPS) carrying the same bearer capability — the photo/place resolvers accept header-then-cookie for custom-place lookup only, never as write auth (PUT still requires the header). Photo replies send `Vary: Cookie`; custom-place photos are `private, no-store` (same URL could serve different owners' bytes), canonical photos keep `private, max-age=86400`.
- CAS writes (`expectedRevision`, Redis Lua); 409 carries the latest trip and is consumed. Drafts are never discarded — recoverable `pendingDraft`, explicit conflict UI ("Replace shared trip with mine" = whole-snapshot overwrite). **Every unsent draft is durable**: `save()`/`localOnly`/409 paths write `biwa:v2:local-draft` BEFORE the PUT (a reload/crash between save and ack loses nothing), `init()` restores it into `pendingDraft` ahead of any refresh (retry replays against the draft's own base revision — never a bumped server revision, so a server advance surfaces a 409 conflict rather than silent overwrite), and `biwa:v2:last-known-trip` holds the last adopted server snapshot for the labelled-stale offline view. Durable copies clear only for server-acknowledged work or explicit `discardPendingDraft()`/conflict-reload (which adopts via the normal lifecycle); a throwing localStorage flips `TripStore.storageAvailable` so the UI never claims persistence it doesn't have. The view is never the raw doc: `_emit` detaches `trip` from `pendingDraft`/`latestServer`/`conflict.*` before overlaying progress, so a 409 can no longer rewrite the durable draft's pinned flags.
- Only idempotent checkbox intents rebase (one retry, after a successful refresh, dropped cleanly if the target was deleted). Reads can't adopt over an open editor or in-flight write (read-generation bump).
- 503 ⇒ temporary `unavailable`, keeps polling; edits hold as pendingDraft and retry on recovery. A guard response (401/403) ⇒ local seed/draft only — cached shared state is never shown.
- Routes: DRIVE + TRAFFIC_UNAWARE + `optimizeWaypointOrder=false` + avoidance prefs + METRIC + narrow mask; 2..27 locations/day incl. endpoints. Provider errors are generic (no key/URL leakage); all API answers `Cache-Control: private, no-store`.
- Google content is transient; route/elevation render only on a real Google Map with attribution — the SVG fallback is a user-owned "stop schematic". Timeline distance gaps are the one permitted off-map metric — text-only legs via `stop-distances.js` with an inline Google terms link and the "road preview, not cycling guidance" note; provider geometry still never renders off-map.
- The Google cache (`lib/biwa/biwa-google-cache.py`) sits inside the Places 30-day content allowance: resolved Google place IDs under `biwa:v2:google:id:*` (no expiry), lat/lng under `biwa:v2:google:coords:*`, normalized details under `biwa:v2:google:details:*`, `places/…` photo names under `biwa:v2:google:photonames:*`, and image bytes (base64, ≤4 MB) under `biwa:v2:google:photo:*` — all 30-day TTL except ids. Route geometry and elevation are still NEVER persisted. All keys are fingerprinted by the record's anchor fields so an edit misses the stale entry. Repeat detail views and repeat photo requests inside the window cost no billed Google call; `/biwa-photo` answers cached bytes with zero provider contact. A failed live details call may surface `source.cachedLocation` (coords only); a cached Google id only shortcuts the search step and still falls through to proximity validation when details fail. Photo responses are `private, max-age=86400` for canonical places (`private, no-store` for custom) with `Vary: Cookie`; JSON responses stay `private, no-store`.
- **Client modules.** Extraction is incremental, not total: `biwa-ride.js` is the application coordinator and still owns view rendering, editors and the stop/endpoint/conflict dialogs — only self-contained controllers moved out. `masthead-scene.js` owns the decorative scene (tree layout, observers, motion gating, GIF keep-alive — `BiwaMastheadScene.init(sceneEl)`, idempotent); `device-pairing.js` owns the pair dialog (`BiwaDevicePairing.init({store,elements,translate,reload,notify})` — `notify` routes blocked/failed attempts to the shared toast's notice tone); `endpoint-change.js` is the pure boundary-edit planner; `offline-cache.js` registers the service worker silently and surfaces genuine connection transitions through the shared toast pill (init `{store,notify,translate}`); `mini-checkin.js` owns the mini bar check-in button's saving→green-tick phase machine (`BiwaMiniCheckin.create({button,translate,onRelease,prefersReducedMotion})`). All load before `biwa-ride.js` in index.html and no-op when their element/global is absent.
- **Automatic offline fallback (online-first).** `service-worker.js` is scoped to `/projects/biwa-ride/` and pre-caches a versioned shell (`biwa-ride-shell-v9`): app HTML under Vercel clean URLs (`./`, `terms`, `privacy` — `index.html`/`.html`/query variants map onto them), local CSS/JS, catalogue/seed and only the art the page references. Every recognized document and allowlisted asset serves bounded NETWORK-first (~3.5s): a validated ok/basic answer always wins online and refreshes its own canonical key in the CURRENT generation cache (a redirect may only refresh a recognized variant of the same document — cleanUrls aliases, never unrelated targets), so the fallback copy tracks the last successful online visit; a rejection/timeout/non-ok answer falls back to that cached copy, and a bare miss preserves the honest error. Unknown in-scope paths fall through, a no-trailing-slash visit is outside the worker's directory scope by default — never claimed — and `SHELL_VERSION` must bump whenever any cached content changes (updates ride the natural waiting-worker lifecycle, no skipWaiting/forced reload). It never intercepts API calls, mutations, Google/maps/tile or third-party requests, and activation evicts only older `biwa-ride-shell-*` caches. There is NO offline mode, toggle or readout — registration is silent and a healthy app says nothing; `offline-cache.js` toasts once per genuine outage (definite `navigator.onLine` loss, or `TripStore.connectionIssue` from a real wire failure — rejected fetch or 5xx, never a guard 401/403 or the provisional boot label) and once on recovery, only after the store proves the wire works (state `saved`, no pendingDraft, no conflict); an `online` event alone never claims synced. Offline reopens the owner's plan/check-ins/notes (localStorage + last-known snapshot); Google details/photos/routes/map tiles are simply unavailable. Priming requires one successful online visit.
- Tests: `tests/biwa-ride/` — `node --test tests/biwa-ride/*.test.js` (rules, trip-store, draft-recovery, app-modules, service-worker, offline-cache) and `venv/bin/python tests/biwa-ride/test_biwa_api.py` (+ `test_biwa_elevation.py`). All external services stubbed.
